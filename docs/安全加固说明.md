# antigravityQuota 安全加固说明

本文件逐条对应 [`docs/隐患.md`](隐患.md) 中的隐患与建议，说明**处置方式**、**代码位置**与
**剩余风险**。

## 一、逐条对照

### 一.1 凭证暴露与明文存储历史

**原隐患**：插件把 Google OAuth 的 access / refresh token 以明文 JSON 保存在用户主目录
（如 `~/.antigravity_cockpit/credentials.json`），任何本机进程都能读取长期有效的 refresh token。

**处置**：

| 措施 | 位置 |
| --- | --- |
| 删除全部凭证存储代码（`credential_storage` / `local_auth_importer` / SecretStorage 读写） | 删除 `src/auto_trigger/**` |
| 删除配套桌面工具桥接（其 `accounts.json` 会落盘 refresh token） | 删除 `src/services/cockpitTools*.ts`、`src/view/accountTree.ts` |
| 删除第三方工具凭证导入（读取 `~/.antigravity_tools/accounts/*`） | 删除 `src/antigravityTools_sync/**` |
| 不再向 `~/.antigravity_cockpit` 写入任何内容（配额缓存、历史、共享配置全部移除） | 删除 `src/services/quota_*.ts`、`src/services/syncSettings.ts` |
| 新增历史残留扫描与一键清理 | `src/shared/legacy_cleanup.ts` + 命令 `antigravityQuota.purgeLegacyData` |
| 源码级断言：只有 `legacy_cleanup.ts` 可以触碰主目录，且不得写入凭证 | `src/test/security_invariants.test.ts` |

**清理命令的安全约束**：

- 只允许删除 `path.join(os.homedir(), '.antigravity_cockpit')` 这一个精确目录；
- 目标为符号链接时**拒绝**处理（防目录穿越 / 诱导删除），遍历时不跟随符号链接；
- 遍历有深度（4 层）与条目（2000）上限，单个文件只读取前 256KB 做特征匹配；
- `~/.antigravity_tools` 属于第三方工具，**只提示、绝不删除**。

### 一.2 OAuth Scope 权限范围过大

**处置**：本分支**完全不使用 OAuth**。

- 删除 `src/auto_trigger/oauth_service.ts`（含 `ANTIGRAVITY_CLIENT_ID` / `ANTIGRAVITY_CLIENT_SECRET`
  与 `cloud-platform`、`userinfo.*`、`cclog`、`experimentsandconfigs` scope 列表）；
- 删除内部 Cloud Code 调用链（`src/shared/cloudcode_client.ts`、`cloudcode_base.ts`）；
- 配额改由本机 language server 自持端口读取，扩展**不申请任何 Google 权限**。

`src/test/security_invariants.test.ts` 会断言源码中不再出现 `cloud-platform`、
`ANTIGRAVITY_CLIENT_ID/SECRET`、`oauth2.googleapis.com` 等字样。

**剩余风险**：无（不再存在授权动作）。

### 一.3 供应链与网络外联不透明

**处置**：

| 原外联点 | 处置 |
| --- | --- |
| 动态公告拉取（`raw.githubusercontent.com`） | 删除 `src/announcement/**` 与 `announcements*.json` |
| Webview 与桌面端的 WebSocket 桥（`ws://…:19528`） | 删除 `src/services/cockpitToolsWs.ts`、`cockpitToolsSync.ts`、`cockpitToolsLocal.ts` |
| 外部工具启动器 / deep link | 删除 `src/shared/cockpit_tools_launcher.ts` |
| 内部 Cloud Code 端点 | 删除 `cloudcode_client.ts` |

**运行时网络出口只剩一处**：`https://127.0.0.1:<port>`（`src/engine/quota_client.ts`
的 `transmit()` 与 `src/engine/hunter.ts` 的 `pingPort()`）。二者主机名硬编码为 `127.0.0.1`，
端口经 `assertValidPort()` 校验，且 `agent: false` 绕过代理。

静态断言：源码中不得出现任何外部主机名（`googleapis.com` / `github.com` / `githubusercontent.com`）。

### 二.1 自动唤醒（Auto Wake-up）—— 风控极高

**处置**：删除 `src/auto_trigger/` 全部实现，包括：

- `scheduler_service.ts`（crontab 解析与定时器）；
- `trigger_service.ts`（周期性向模型发送空请求以触发配额重置）；
- `controller.ts`（自动触发总控）；
- 配额快照发布流程中的 `checkQuotaResetTrigger()` 调用点（随 `reactor.ts` 一并删除）。

现在扩展只做**只读查询**（`GetUserStatus`），不会再产生任何模型调用。

### 二.2 多账号自动切换 —— 风控极高

**处置**：删除多账号存储、`accountSwitchService.ts`、账号树视图 `accountTree.ts`、
WS 桥的 `pluginSwitchAccount` / `pluginSetSwitchMode` 处理，以及 `extension.ts` 中的
启动自动同步逻辑。当前版本**只能查看当前登录账号**的配额。

### 二.3 模拟官方客户端调用内部 API

**处置**：删除了通过 OAuth token 调用 `v1internal:loadCodeAssist` / `onboardUser` /
`fetchAvailableModels` 的整条链路（`cloudcode_client.ts`）。

保留的 `GetUserStatus` 是 Antigravity 自己的 language server 为**其宿主编辑器扩展**
提供的接口，端口与 CSRF token 均由该进程自持，不再伪装其它客户端身份去访问云端。

**剩余风险（如实说明）**：`GetUserStatus` 属于非公开接口，官方若调整接口或收紧
language server 的扩展侧访问，本扩展可能失效——但那是**功能失效**，不涉及账号风控封禁面。
本扩展自身不产生模型调用，也不做多账号轮换，因此不构成滥用特征。

### 二.4 高频状态轮询

**处置**（`src/shared/constants.ts` + `src/shared/env_guard.ts` + `src/engine/poller.ts`）：

| 措施 | 值 |
| --- | --- |
| 默认刷新间隔 | 300 秒（原 120 秒 / 最小 10 秒） |
| **硬下限**（配置值会被夹取） | 60 秒 |
| 上限 | 3600 秒 |
| 抖动 | ±10%（避免多窗口同步打点） |
| 失败退避 | `base × 2^failures`，上限 30 分钟，成功后立即回落 |
| 并发控制 | single-flight，同一时刻只有一个请求 |
| 手动刷新冷却 | 60 秒 |

### 三.2 清理本地残留明文凭据

内置命令 `Antigravity: Purge Legacy Plaintext Credentials`：

- 激活时静默扫描一次，发现疑似含 `refresh_token` / `access_token` / `client_secret` 的文件时弹窗提示；
- 用户确认后删除 `~/.antigravity_cockpit` 整个目录（含旧版缓存与 `credentials.json` / `accounts.json`）；
- 对 `~/.antigravity_tools` 只提示，不动它。

> 注：删除 Google 账号侧的第三方授权（隐患.md 三.1）需用户在
> <https://myaccount.google.com/connections> 自行操作，扩展无法代劳。

## 二、额外加固（隐患.md 未列，但属同类风险）

| 类别 | 措施 | 位置 |
| --- | --- | --- |
| 命令注入 | 进程名只允许 `PROCESS_NAMES` 白名单；PID 必须是正整数；拒绝外部字符串拼入 shell | `src/engine/strategies.ts` |
| 输入校验 | CSRF token 限字符集 `[A-Za-z0-9_-]` 且 ≤256 字符；端口为 1–65535 整数 | `src/shared/env_guard.ts` |
| 内存放大 | 命令输出与 HTTP 响应均设 4MB 上限，超限即断开 | `strategies.ts` / `quota_client.ts` |
| Webview XSS | 严格 CSP（nonce 脚本、无 `unsafe-inline`/`unsafe-eval`、`connect-src 'none'`）；webview 脚本不使用任何原始 HTML 注入 API | `src/view/dashboard.ts` / `webview/dashboard.js` |
| Tooltip 注入 | 状态栏 Markdown 设为**非受信**（`isTrusted = false`），服务端文本一律转义 | `src/view/status_bar.ts` |
| CSP nonce 熵 | 由 `Math.random()` 改为 `crypto.randomBytes(16)` | `src/view/dashboard.ts` |
| 错误分类 | 区分 `AntigravityError`（服务端报错）与 `ConnectionError`（连接层失败），仅在后者触发重新探测，避免无意义重连风暴 | `src/shared/errors.ts` |
| 资源释放 | status bar / poller / logger / webview 命令均注册到 `context.subscriptions`，`deactivate` 时清理 | `src/extension.ts` |
| 依赖面 | 移除 `sql.js`（wasm SQLite）与 `cron-parser`，运行时依赖为 **0** | `package.json` |
| 代码面 | 删除 `~3.3 万行` 中的约 90%，仅保留 33 个源文件 | `src/` |

## 四、遗留与取舍（如实列出）

1. **需要在 WSL/远程容器内运行编辑器时**，本机 language server 探测可能不可用——这是上游既有局限，
   本次未实现 WSL 主机回环转发。
2. **本地 TLS 校验证书被关闭**（`rejectUnauthorized: false`）：Antigravity language server
   使用自签名证书，且连接固定为 `127.0.0.1`。由于扩展**不再通过该连接传递任何长期凭证**
   （只有由对端进程自己生成的 CSRF token），本地中间人可窃取的信息面已极小；如需彻底消除，
   需实现本地证书指纹锁定（Pinning）。
3. **非公开接口稳定性**：`GetUserStatus` 若发生不兼容变更，本扩展会显示离线，
   不会静默降级到其它（更高风险的）数据源。
